## Non-negotiable operating rules

1. Read `CLAUDE.md`, `SOUL.md`, `USER.md`, today/yesterday in `memory/`, and `MEMORY.md` before starting.
2. Read the complete `.claude/skills/lofn/SKILL.md`, its execution protocol, `.claude/skills/lofn-image/SKILL.md`, and `.claude/skills/lofn-qa/SKILL.md`. Use the repository's full Lofn pipeline; do not replace it with an improvised prompt.
3. Create a new run directory. Acquire its lock as the first write:

   ```bash
   python3 scripts/run_lock.py acquire output/<run-slug> --run-slug <run-slug> --engine claude
   ```

   Exit code 3 means stop. Never break or route around a lock.
4. Use only an officially supported, currently permitted browser-control surface attached to the user's authenticated session. If NightCafe is unavailable or a safety policy blocks it, stop and ask the user to perform the browser step. Do not switch surfaces to evade a restriction.
5. Keep every generation **private**. Do not publish, submit, evolve a published image, or edit account settings.
6. Follow `vault/AUTONOMY.md`: use a model visibly marked **Free** or **Unlimited** in the live NightCafe UI. Do not spend credits or select a paid/PRO setting without the Scientist's explicit approval.
7. Generate **one image only** per cycle. Disable any multi-image count or batch option.
8. Never use a prior winning image/prompt as generator context. Past outputs are judge-side evidence only; Golden Seed and distilled lessons may guide generation.
9. Avoid children by default. Use explicit positive adult descriptors when a human appears; do not put negated child-related terms into a NightCafe prompt.

## Prepare the candidate pool once

If the requested subject already has a completed Lofn image run, use its ranked prompts. Otherwise run Phase 0/1 and `lofn-image` through Steps 00–10 to produce the canonical 24 prompts and run `lofn-qa` on them. This prompt-pool work happens once; the browser loop below stays serial.

Select the first candidate using this order:

1. one-sentence no-title thumbnail read;
2. unmistakable action and subject topology;
3. one dominant spectacle layer;
4. personality-specific material/palette;
5. anatomy and geometry risk;
6. model fit.

Record why the first prompt was chosen in `output/<run-slug>/render-loop/GENERATION_LOG.md`.

## The serial render → inspect → learn loop

For generation `NN`:

### 1. Freeze the exact request

Create `output/<run-slug>/render-loop/gNN/REQUEST.md` containing:

- exact prompt text;
- model name and whether the UI says Free/Unlimited;
- aspect ratio, resolution, seed/noise/evolve settings, and image count = 1;
- the single hypothesis being tested;
- what changed from `gNN-1` (maximum three deliberate changes).

Do not edit this file after clicking Generate.

### 2. Generate exactly once

In NightCafe, verify the visible price is zero immediately before the click. Generate one private image. If the price is nonzero, stop without clicking.

Wait for completion, then download the original-resolution image through the normal UI. Save it as:

`output/<run-slug>/render-loop/gNN/gNN-original.<ext>`

Also record the creation URL/job ID and final settings in `RESULT.md`. Do not publish it.

### 3. Blind read first

Before rereading the prompt, open only the image and answer in `BLIND_READ.md`:

- What is happening, in one sentence?
- Who/what is the subject?
- Where does the eye land first, second, third?
- What is confusing or admits a plausible alternate reading?
- What feels specific to Lofn rather than generic prestige fantasy?

If the blind description misses the intended event, that is a render failure even when the image is beautiful.

### 4. Inspect at two scales

Make and inspect a 128 px thumbnail. Then inspect the original at full resolution with targeted crops. Record pass/fail evidence for:

- no-title theme/action legibility at 128 px;
- subject/background silhouette separation;
- body topology and attachment points;
- hands, eyes, limbs, joints, repeated geometry, and object contact;
- adult-read/child-read risk;
- text, watermark, logo, or accidental signature;
- brightest contrast explaining the action rather than decorating it;
- one dominant spectacle layer rather than competing prestige materials;
- requested palette, medium, pose, and spatial relationship;
- all four corners and cropped edges.

When the Scientist names a defect, inspect **that exact defect** in its own crop. Verifying the rule added to the prompt is not proof the defect was repaired.

### 5. Compare intent to result

Write `EVALUATION.md` with four sections:

- **Survived:** prompt intentions visibly present.
- **Smoothed/lost:** requested properties the model ignored or weakened.
- **Generator gifts:** deviations better than the request and worth preserving.
- **Blocking defects:** ambiguity, anatomy, geometry, safety, or genericness that prevents advancement.

End with one verdict: `KEEP`, `REPAIR`, or `REJECT`.

### 6. Write the learning delta

Append one row to `GENERATION_LOG.md`:

| Gen | Hypothesis | Blind read | Survived | Failed | Gift | Next delta | Verdict |
|---|---|---|---|---|---|---|---|

The next delta must name no more than three changes. Preserve every verified success explicitly; do not rewrite the entire prompt and lose what worked.

Useful repair order:

1. legibility/event;
2. anatomy/topology/contact;
3. focal hierarchy;
4. palette/material;
5. ornamental detail.

### 7. Clean-context veto

Before generation `NN+1`, ask a fresh visual-judge context to inspect the image without seeing the generating discussion. Give it the image first, then the brief. Its job is to find a plausible misread and the one defect most likely to earn a NightCafe 3. `KEEP` requires no unresolved structural ambiguity. The generating context does not grade its own work.

Only after this evaluation is written may Claude prepare and launch generation `NN+1`.

## Stop conditions

Stop the loop and report to the Scientist when any one occurs:

- six serial generations have completed;
- a clean-context judge and the structural sweep both return an unambiguous `KEEP`;
- the same defect survives three attempts with no measured progress;
- no free/unlimited model is available;
- browser access, account state, generation policy, or cost is uncertain;
- publication/submission would be the next action.

Write the run `INDEX.md` last, heartbeat at every completed generation, and release the lock after the index:

```bash
python3 scripts/run_lock.py heartbeat output/<run-slug> --phase "gNN evaluated; next delta written"
python3 scripts/run_lock.py release output/<run-slug> --phase "serial render loop complete; private artifacts only"
```
